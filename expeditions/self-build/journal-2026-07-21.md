# Journal: expedition framework — 2026-07-21

## The day's discoveries

The framework packaged itself in one expedition without the packaging turning prescriptive: no template gained steps, no schema gained an obligation, and the closed set of eleven event types held — nothing had to be forced into the wrong type, and the `account` escape hatch was used only once in the example, never in this log.

## Failed crossings

None. The nearest thing was the browser refusing file:// snapshots when verifying the map; serving over localhost held.

## Corrections to the map

The plan assumed the skill folder would need "spec essentials" chosen carefully; in practice the whole spec minus examples fits, and vendoring `journey-state.md` plus the schema is enough for an installed skill to keep a valid log.

## Questions left open

- Where the templates fought back: the dispatch template wants a "Riders" section, but riders are log-primary events — a dispatch that carries a rider records it twice (once as prose, once as a log line). Is the duplication a feature (the document has voice) or a smell? Left as designed: markdown for voice, log for the record.
- The `word` event requires `answer` but the patron rarely writes the log line themselves; the frontiersman transcribes it. The spec is silent on transcription; the actor field says `patron` because the word is theirs. Worth a sentence in the spec someday if it confuses.
- Whether `expedition.skill` (the built zip) should be committed or only built on demand — a distribution question, reserved to the patron.
